# cvpr_paper_ckecker

Computer Vision & Pattern Recognition 関連の最新論文をチェックする。

## collect_arxiv_cv.py 仕様

arXiv の cs.CV（Computer Vision and Pattern Recognition）論文を期間指定で集め、和訳・所属企業・コード公開・入力／出力データ・観点 15 種を付けた一覧を CSV・xlsx・HTML で出力する。

### 実行方法

- `run_collect_arxiv_cv.bat` をダブルクリック（直近 3 日分）。結果は `result` フォルダに保存するだけで、フォルダやファイルは開かない。
- コマンドラインから:

```bash
python collect_arxiv_cv.py --start 2026-10-14 --end 2026-10-16
```

| オプション | 既定値 | 内容 |
|---|---|---|
| `--start` | `--end` から `--days` 日分さかのぼった日 | 開始日（日本時間、YYYY-MM-DD） |
| `--days` | 3 | `--start` 省略時に集める日数（`--end` を含む） |
| `--end` | 今日 | 終了日（日本時間、この日を含む） |
| `--output` | `result/<実行日>/arxiv_csCV_<start>_to_<end>.csv` | CSV の出力先。xlsx と HTML は同じ場所・同じ名前で出力 |
| `--no-translate` | なし | 翻訳サービスにタイトルを送らない（和訳列は空欄） |
| `--html-interval` | 3.0 | arXiv HTML ページの取得間隔（秒） |
| `--index-only` | なし | 収集せず、`result/index.html` だけを作り直す |

必要環境: Python 3.9 以上、`openpyxl`、Windows では `tzdata`（`requirements.txt`。bat は未導入なら自動で入れる）。

### 処理の流れ

1. **論文一覧の取得**: まず arXiv の検索 API（`export.arxiv.org/api`、`cat:cs.CV` と投稿日時で検索、500 件ずつ）で取得する。API が失敗したとき（429 など）は arXiv OAI-PMH（`oaipmh.arxiv.org`、arXivRaw 形式、cs 分野）に切り替え、1 日分ずつ取得する（何日分もまとめて頼むとサーバーの応答が 3 分を超え、503 になるため）。どちらも 3 秒に 1 回。初版（v1）の投稿日時が期間内（日本時間）の論文を残す。クロスリストも含む。新しい順に並べる。
2. **和訳**: タイトルを外部の翻訳 API（`translate.projectsegfau.lt`）で日本語に訳す。4 本並列、失敗時は 5 回までやり直し、だめなら空欄。
3. **所属企業**: `arxiv.org/html/<ID>` を 1 本ずつ取得し、著者欄の所属から企業名（42 社）を正規表現で探す。Meta・Apple など一般語と紛らわしい 9 社は大文字小文字を区別し、社名らしい形のときだけ一致。HTML 版が無い論文は空欄。
4. **コード公開**: アブストラクトのみで判定。
   - あり: GitHub / GitLab / Bitbucket / Codeberg / Hugging Face / github.io の URL、または「code is available」「project page」など
   - 公開予定: 「code will be released」など
   - なし: 上記以外
5. **入力・出力データ**: タイトルとアブストラクトのキーワードから、技術の入力と出力のデータの種類（画像・動画・テキスト・点群・深度・マスク・行動など）を推定し、多い順に最大 3 つを「・」でつないで書く。手がかりは「from / given / takes …」（入力）、「generates / predicts / estimates …」（出力）、「text-to-image」のような X-to-Y 表現、セグメンテーション・検出・VQA などのタスク名。
6. **観点の判定**: タイトルとアブストラクトのキーワード（正規表現）で 15 観点を判定し、該当すれば「●」。
7. **出力**: `result/<実行日>/`（例: `result/2026-10-17/`）に CSV・xlsx・HTML を書き出す。フォルダは自動で作る。あわせて `result/index.html`（全結果へのリンク一覧。実行日の新しい順、期間と件数つき）を作り直す。

通信は失敗時（406・429・5xx・ネットワーク）に、15・30・60・120 秒あけて最大 4 回やり直す。arXiv の利用条件（3 秒に 1 回・接続 1 本）に合わせている。

### 出力の列

| 列 | 見出し | 内容 |
|---|---|---|
| A | 発表日 | 初版の投稿日（日本時間） |
| B | 英文タイトル | xlsx・HTML では alphaXiv へのリンク |
| C | 和訳タイトル | |
| D | 著者の所属する企業名 | `; ` 区切り。大学のみなら空欄 |
| E | ソースコードの開示有無 | あり / 公開予定 / なし |
| F | 入力データ | 技術の入力データの種類（キーワードによる推定。例: 画像・テキスト） |
| G | 出力データ | 技術の出力データの種類（キーワードによる推定。例: マスク、行動、3D データ） |
| H | 物体検出・追跡 | 観点① |
| I | 画素単位セグメンテーション | 観点② |
| J | 画像・動画編集 | 観点③ |
| K | 画像・動画生成 | 観点④ |
| L | 画像・動画から3D・深度 | 観点⑤ |
| M | 3D物体検出・セグメンテーション | 観点⑥ |
| N | 3D生成・編集 | 観点⑦ |
| O | 画像・動画・3Dからテキスト | 観点⑧ |
| P | 高速化・軽量化・学習効率化 | 観点⑨ |
| Q | 非RGBセンサー使用 | 観点⑩ |
| R | ロボット動作 | 観点⑪ ロボットの動作に関係（操作・把持・移動・VLA など） |
| S | 自動運転 | 観点⑫ 自動運転に関係（運転シーン・BEV・nuScenes・交通など） |
| T | 医療画像 | 観点⑬ 医療画像に関係（CT・MRI・X 線・病理・臨床など） |
| U | 産業画像 | 観点⑭ 産業画像に関係（外観検査・欠陥検出・製造など） |
| V | 人物 | 観点⑮ 人物の画像・動画・3D データに関係（顔・体の姿勢や動き・手・アバター・服・歩行者・ディープフェイクなど） |
| W | arXiv ID | HTML では表示しない |
| X | URL | arXiv の論文ページ。HTML では表示しない |
| Y | alphaXiv URL | alphaXiv の論文ページ。HTML では表示しない |

- **CSV**: UTF-8（BOM 付き）。Excel でそのまま開ける。見出しは 1 行（大分類名の行は無い）。
- **xlsx**: シート名 `cs.CV`。1 行目は大分類名（F〜G 列「入出力データ」、H〜Q 列「タスク」、R〜V 列「アプリケーション」をそれぞれセル結合）、2 行目が列の見出し。2 行目までを固定、2 行目にフィルター、URL と英文タイトルはクリックで開くリンク、発表日は日付型。
- **HTML**: ブラウザで開く 1 ファイル（外部ファイル・ネット接続は不要）。xlsx と同じ大分類名の行を列の見出しの上に置き、見出しを固定、列ごとの絞り込み（タイトル・和訳・入力データ・出力データは文字入力。企業名は企業ごとのドロップダウンで、「(企業あり)」「(空欄)」も選べ、複数社の論文はどの社を選んでも出る。発表日・コード有無・観点も選択式）、見出しクリックで並べ替え、表示件数の表示、絞り込みの解除ボタン。表示は A〜V 列で、arXiv ID と 2 つの URL の列は表示しない（英文タイトルから alphaXiv を開ける）。ダークモードに対応。

### 制約・注意点

- 当日の投稿は arXiv に掲載されるまで出てこない（掲載は翌営業日が多い）。
- 企業名・コード公開・入力／出力データ・観点はキーワードによる自動判定で、誤りや漏れがある。特に入力／出力データは目安で、空欄になる論文もある。
- タイトルが外部の翻訳サービスに送られる（`--no-translate` で止められる）。
- タイトルの数式は LaTeX 表記のまま（例: `$\Delta$`）。
- 3 日分（約 350 本）で約 20 分かかる。大半は HTML の取得待ち。

### 定期実行（GitHub Actions）

`.github/workflows/collect.yml` により、毎週土曜 10:00（日本時間）ごろに、実行日の 2 日前までの 7 日分（前週金曜〜木曜）を収集し、`result/<実行日>/` に CSV・xlsx・HTML を追加してこのリポジトリへコミットする。

- 期間を 2 日前で切るのは、金曜以降の投稿が arXiv に掲載されるのが翌週月曜になるため。期間内の論文は実行時点ですべて掲載済みで、金・土曜の投稿は翌週の期間で拾われる。
- 収集が 0 件だったときはコミットしない。
- arXiv のサーバーが混んでいて論文一覧を取得できなかったときは、20 分あけて最大 3 回まで実行し直す。
- GitHub の混雑状況により、開始が数分〜数十分遅れることがある。
- 手動実行: リポジトリの **Actions** タブ → **Collect arXiv cs.CV papers** → **Run workflow**（日数を指定可能。期間の終わりは常に実行日の 2 日前）。
- 公開リポジトリで 60 日間コミットが無いと、定期実行は GitHub により自動で停止される（結果のコミットがあれば継続）。
